  • 게시글 카드 — 제목, 스터디 제목, 작성자, 작성 날짜, 댓글 수, 좋아요 수, 최근 댓글(2개), 메모칸, 사진
04

04 DB 구조

테이블 연결 관계

  • 사용자 → 게시물 : 한 사용자가 여러 게시물 작성 가능 (ls_users 1 : N ls_posts)
  • 사용자 → 댓글 : 한 사용자가 여러 댓글 작성 가능 (ls_users 1 : N ls_comments)
  • 게시물 → 댓글 : 한 게시물에 여러 댓글 작성 가능 (ls_posts 1 : N ls_comments)
  • 댓글 → 대댓글 : 한 댓글에 여러 대댓글 작성 가능 (ls_comments 1 : N ls_comments, 자기참조)
  • 게시물 → 사진 : 한 게시물에 여러 사진 첨부 가능 (ls_posts 1 : N ls_post_images)
  • 카테고리 → 게시물 : 한 카테고리에 여러 게시물 소속 가능 (ls_categories 1 : N ls_posts)
  • 사용자 ↔ 게시물(좋아요) : 좋아요 기록으로 다대다 관계 연결 (ls_post_likes)
  • 사용자 ↔ 댓글(좋아요) : 좋아요 기록으로 다대다 관계 연결 (ls_comment_likes)

마이페이지 화면 연결 방법

화면조회 방법
내가 쓴 글ls_posts에서 user_id = 내 id로 조회
내가 쓴 댓글ls_comments에서 user_id = 내 id로 조회
좋아요한 게시글ls_post_likes에서 user_id = 내 id인 항목을 찾은 뒤, 연결된 ls_posts 조회
모든 테이블은 RLS(Row Level Security) 적용 — 본인 데이터(user_id = auth.uid())만 수정·삭제 가능하도록 DB 레벨에서 강제. ls_post_images는 Storage 버킷 업로드 권한을 로그인 사용자로 제한하고 이미지 확장자·용량을 검증한다. (자세한 내용은 05 보안 정책 참고)

05 보안 정책

이메일 인증 절차는 생략하고 중복 검사만 진행하되, 그 외 항목은 권장 방향을 채택한다.

우선순위항목비고
필수이메일 중복 검사(인증 메일 X)회원가입 시 DB 기준 중복 여부만 확인
필수Supabase Auth 사용비밀번호 직접 해싱 구현하지 않음
필수RLS(Row Level Security) 정책게시글 · 댓글 · 마이페이지를 auth.uid() 기준 본인 데이터만 수정 · 삭제 가능하도록 DB 레벨에서 강제
필수게시글 · 댓글 XSS 방지본문 렌더링 시 sanitize 또는 이스케이프 처리
필수사진 업로드 검증확장자/MIME 화이트리스트, 크기 제한, Storage 버킷 권한 설정
필수service_role 키 비노출클라이언트에는 anon/publishable 키만 사용

# 나만의 커뮤니티 기획서

## 커뮤니티 주제
- 스터디

## 디자인 스타일
- **사이트 이름**: Leetudy
- **색상 테마**: 파스텔톤의 자연색(나무, 잎, 하늘 등)
- **분위기**: 친근한

## 특별한 기능 아이디어
- 사진 업로드, 메모칸, 댓글, 좋아요
- 게시글 검색(제목/내용/작성자)
- 스터디 주제별 카테고리 분류(태그)

## 페이지별 특징

### 회원가입 페이지
- 이메일(계정)
  - 가입 확인 메일(이메일 인증) 절차는 두지 않음 — **이메일 중복 검사만 진행**
- 비밀번호
- 비밀번호 확인(오타 검증용)
- 닉네임(이름)
- 전화번호
- 회원가입 버튼

### 로그인 페이지
- 이메일(계정) 입력
- 비밀번호
- 로그인 버튼
- 회원가입 버튼
- 비밀번호 찾기 버튼

### 게시물 목록
- 검색창(제목/내용/작성자)
- 카테고리(스터디 주제) 필터
- 글쓰기 버튼
- 페이지네이션 or 무한 스크롤
- 게시글 카드
  - 게시글 제목
  - 스터디 제목
  - 작성자
  - 작성 날짜
  - 댓글 수
  - 좋아요 수
  - 최근 댓글(2개)
  - 메모칸
  - 사진 업로드

### 게시물 상세
- 게시글 제목
- 작성자
- 작성 날짜
- 게시글 내용(본문)
- 좋아요 수 + 좋아요 버튼
- 수정/삭제 버튼(작성자 본인에게만 노출)
- 댓글
  - 댓글 작성자
  - 댓글 내용
  - 댓글 작성 시간

### 글쓰기 / 수정 페이지
- 스터디 주제(카테고리) 선택
- 게시글 제목
- 게시글 내용(본문)
- 사진 업로드
- 등록/수정 버튼, 취소 버튼

### 마이페이지
- 프로필(닉네임, 프로필 사진) 수정
- 비밀번호 변경
- 내가 쓴 글 목록
- 내가 쓴 댓글 목록
- 좋아요한 게시글 목록

### 댓글 기능
- 댓글 좋아요
- 대댓글
- 댓글 수정/삭제(작성자 본인에게만 노출)

## 보안 정책

이메일 인증 절차는 생략하되, 그 외 항목은 권장 방향을 그대로 채택.

| 우선순위 | 항목 | 비고 |
|---|---|---|
| 필수 | 이메일 중복 검사 (인증 메일 X) | 회원가입 시 DB 기준 중복 여부만 확인 |
| 필수 | Supabase Auth 사용 | 비밀번호 직접 해싱 구현하지 않음 |
| 필수 | RLS(Row Level Security) 정책 적용 | 게시글/댓글/마이페이지 모두 `auth.uid()` 기준으로 본인 데이터만 수정·삭제 가능하도록 DB 레벨에서 강제 |
| 필수 | 게시글/댓글 XSS 방지 | 본문 렌더링 시 sanitize 또는 이스케이프 처리 |
| 필수 | 사진 업로드 검증 | 확장자/MIME 화이트리스트, 파일 크기 제한, Storage 버킷 권한 설정 |
| 필수 | `service_role` 키 비노출 | 클라이언트에는 `anon`/`publishable` 키만 사용 |
| 권장 | 로그인 실패 횟수 제한 | 무차별 대입 공격 방지 |
| 권장 | 좋아요 중복 방지 | (user_id + post_id) 유니크 제약 |
| 선택(추후) | Rate Limiting | 게시글/댓글 작성 빈도 제한 |
| 선택(추후) | 캡차 | 스팸/봇 가입 방지 |
